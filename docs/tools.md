# Tool reference

dogpolicies-mcp 0.3.0, generated by `node scripts/docs.mjs` from the live definitions. Every tool returns readable markdown by default and structured JSON with `response_format: "json"`; every result starts with a citation and ends with the attribution line.

## `dogpolicies_search_places`

**Search places** · since 0.1.0

Search parks, beaches, trails, hotels, campgrounds and cabin resorts in California and Nevada by name, location and dog rules.

Returns one page of places with a one-line answer ("Yes, on a leash no longer than 6 feet."), status (yes, yes_restricted, no, varies), verification date and page URL. Each result includes the place id.

Examples:
- "Off-leash beaches near San Diego" -> type="beach", off_leash=true, near={lat:32.72, lon:-117.16}
- "Can I bring my dog to Point Lobos?" -> query="Point Lobos"
- "State parks in Marin County that allow dogs" -> type="park", county="Marin", dogs_allowed=true
- "Lake Tahoe beaches in Nevada that allow dogs" -> type="beach", state="NV", dogs_allowed=true
- "Off-leash dog parks in Las Vegas" -> type="park", off_leash=true, county="Clark", state="NV"
- "RV parks in Fresno County that take dogs" -> type="campground", county="Fresno", dogs_allowed=true
- "Dog-friendly cabins in June Lake" -> type="cabins", query="June Lake", dogs_allowed=true
- "Restaurants with a dog-friendly patio in Alameda" -> type="restaurant", query="Alameda"

Annotations: read-only true, destructive false, idempotent true, open-world false.

| Input | Type | Meaning |
|---|---|---|
| `query` | string (min length 2, max length 100) | Words to match in the name, city, county or brand |
| `type` | `lodging`, `campground`, `cabins`, `beach`, `park`, `trail`, `restaurant` | Kind of place; campground covers campgrounds and RV parks (some also rent cabins), cabins covers cabin resorts with no campground, restaurant covers restaurants, cafes, bars, breweries and tasting rooms (dogs on the patio, by the owner's published policy) |
| `dogs_allowed` | boolean | true: only places that allow dogs somewhere; false: only places that do not |
| `off_leash` | boolean | true: only places where the managing agency allows dogs off leash, at least at some times |
| `state` | `CA`, `NV` | "CA" or "NV". Also tells apart counties with the same name, such as Humboldt. |
| `county` | string (min length 2, max length 40) | County name without "County", in California or Nevada, e.g. "Monterey" or "Washoe" |
| `region` | `north-coast`, `shasta-cascade`, `gold-country`, `high-sierra`, `bay-area`, `central-coast`, `central-valley`, `inland-empire-deserts`, `los-angeles`, `orange-county`, `san-diego`, `reno-tahoe-nevada`, `las-vegas-southern-nevada`, `northern-central-nevada` | Region id, e.g. central-coast, san-diego or reno-tahoe-nevada |
| `area` | string (min length 2, max length 60) | Area id, the name a traveler gives the trip: san-francisco, east-bay, peninsula, south-bay, north-bay, lake-tahoe, big-sur, mendocino-coast, yosemite, death-valley |
| `near` | object | Limit to places near a point; results are sorted by distance |
| `limit` | integer (min 1, max 50, default `10`) | Maximum results to return |
| `offset` | integer (min 0, max 9007199254740991, default `0`) | Results to skip, for pagination |
| `response_format` | `markdown`, `json` (default `"markdown"`) | 'markdown' for readable text, 'json' for structured data |

Output fields: `as_of`, `license`, `attribution_text`, `attribution_url`, `total`, `count`, `offset`, `has_more`, `places` (more may be added; none removed).

## `dogpolicies_near`

**What is near a town** · since 0.2.0

Anything for dogs around a town, county or point: everything dog-related nearby, grouped by kind: beaches, parks, trails, hotels, campgrounds, cabins, places to eat and rest areas, each sorted by distance, with the dog rule and citation for each. Answers "what can I do with my dog there?" for a named place.

Takes a town or county name (no coordinates needed) or a point.

Examples:
- "What can my dog do in Carmel?" -> place="Carmel"
- "Dog beaches and parks around South Lake Tahoe" -> place="South Lake Tahoe", types=["beach","park"]
- "Anything dog-friendly within 5 miles of here" -> near={lat:36.6, lon:-121.9}, radius_miles=5

Annotations: read-only true, destructive false, idempotent true, open-world false.

| Input | Type | Meaning |
|---|---|---|
| `place` | string (min length 2, max length 80) | A city, county or area in California or Nevada, e.g. "Monterey", "South Lake Tahoe", "Washoe County, NV", "Las Vegas", "East Bay" or "Lake Tahoe" |
| `near` | object | A point instead of a town; give one of place or near |
| `radius_miles` | number (min 1, max 100, default `15`) | Search radius in miles around the town or point (an area is its own boundary; the radius is ignored) |
| `types` | array of `beach`, `park`, `trail`, `lodging`, `campground`, `cabins`, `restaurant`, `rest_area`, `stop` | Kinds to include; all by default |
| `dogs_allowed_only` | boolean (default `true`) | Leave out places where dogs are not allowed |
| `per_type` | integer (min 1, max 20, default `5`) | Nearest results to show per kind |
| `response_format` | `markdown`, `json` (default `"markdown"`) | 'markdown' for readable text, 'json' for structured data |

Output fields: `as_of`, `license`, `attribution_text`, `attribution_url`, `center`, `label`, `radius_miles`, `total`, `groups` (more may be added; none removed).

## `dogpolicies_get_place`

**Get place details** · since 0.1.0

The full record for one place you already know by id: every dog rule with its display text, the rules list, and each source with its URL, publisher, capture date and quote. A place on I-5 in California also carries its axis position (s meters from San Ysidro on the I-5 centerline, Caltrans mile, meters off the road, side of northbound travel, road elevation, strip) and, when it is the dog side of a paired stop, that pair: the exit and the people-stops near it (counted from OpenStreetMap, never named, not verified for restrooms).

Takes a place id, as returned in every search result. Example: id="carmel-beach".

Annotations: read-only true, destructive false, idempotent true, open-world false.

| Input | Type | Meaning |
|---|---|---|
| `id` (required) | string (min length 2, max length 120) | Place id, e.g. "fort-funston" |
| `response_format` | `markdown`, `json` (default `"markdown"`) | 'markdown' for readable text, 'json' for structured data |

Output fields: `id`, `uid`, `name`, `type`, `status`, `answer`, `citation`, `confidence`, `confirmed_by`, `freshness`, `verified_at`, `url`, `source_urls`, `record_license`, `as_of`, `license`, `attribution_text`, `attribution_url`, `facts`, `rule_records`, `not_stated`, `rules`, `sources`, `review_due`, `axis`, `paired_stop` (more may be added; none removed).

## `dogpolicies_compare_places`

**Compare places side by side** · since 0.2.0

Which one is better for a dog? Compare two to six places on the facts that decide a dog trip: dogs allowed, leash rule, where dogs may go, pet fee, weight limit, pets per room, restrictions, plus confidence, freshness and who confirmed each record. One row per fact, one column per place, every place with its citation.

Answers "which one?" between candidates; ids come from any search result. Example: ids=["carmel-beach","asilomar-state-beach"].

Annotations: read-only true, destructive false, idempotent true, open-world false.

| Input | Type | Meaning |
|---|---|---|
| `ids` (required) | array of string | Two to six place ids from search results |
| `response_format` | `markdown`, `json` (default `"markdown"`) | 'markdown' for readable text, 'json' for structured data |

Output fields: `as_of`, `license`, `attribution_text`, `attribution_url`, `places`, `rows` (more may be added; none removed).

## `dogpolicies_plan_trip`

**Plan a trip with a dog** · since 0.2.0

Plan a stay in a California or Nevada town with a dog, in one call: where to stay (hotels, campgrounds and cabins that will take this dog, with the pet fee for the whole stay worked out), what to do (beaches, parks and trails that allow dogs, nearest first) and where to eat (patios that take dogs), every item with its citation. When the town is within 10 miles of I-5 in California, the result also carries the drive leg on the I-5 axis: the town's position (Caltrans mile and s meters from San Ysidro), the next family stops (restrooms and a pet area or dog park stated by their official source) in each direction within 60 miles, and the paired stops (an exit with people-stops nearby, counted from OpenStreetMap and never named, matched to the nearest dog-legal place) within 10 miles.

Inputs: the town or county and the dog: weight, how many dogs, nights, and the most the user will pay in pet fees.

Examples:
- "Three nights in Monterey with our 70 lb Lab, pet fees under $100" -> place="Monterey", dog_weight_lb=70, nights=3, max_total_fee=100
- "A weekend in South Lake Tahoe with two small dogs" -> place="South Lake Tahoe", dogs=2, nights=2
- "Camping near Mammoth Lakes with a dog" -> place="Mono County", stay_types=["campground","cabins"]

Annotations: read-only true, destructive false, idempotent true, open-world false.

| Input | Type | Meaning |
|---|---|---|
| `place` | string (min length 2, max length 80) | A city, county or area in California or Nevada, e.g. "Monterey", "South Lake Tahoe", "Washoe County, NV", "Las Vegas", "East Bay" or "Lake Tahoe" |
| `near` | object | A point instead of a town; give one of place or near |
| `radius_miles` | number (min 1, max 100, default `15`) | Search radius in miles around the town or point (an area is its own boundary; the radius is ignored) |
| `dog_weight_lb` | number (min 1, max 250) | The dog's weight in pounds |
| `dogs` | integer (min 1, max 4, default `1`) | Number of dogs |
| `nights` | integer (min 1, max 30, default `1`) | Nights of the stay |
| `max_total_fee` | number (min 0, max 5000) | Most the guest will pay in pet fees for the whole stay, USD |
| `stay_types` | array of `lodging`, `campground`, `cabins` (default `["lodging","campground","cabins"]`) | Kinds of stay to consider |
| `include_possible` | boolean (default `true`) | Include stays that need a call to confirm |
| `per_section` | integer (min 1, max 15, default `5`) | Results per section |
| `response_format` | `markdown`, `json` (default `"markdown"`) | 'markdown' for readable text, 'json' for structured data |

Output fields: `as_of`, `license`, `attribution_text`, `attribution_url`, `label`, `radius_miles`, `asked`, `stays`, `stay_counts`, `outings`, `i5` (more may be added; none removed).

## `dogpolicies_find_hotels`

**Find hotels for a dog** · since 0.1.0

Find hotels and motels in California and Nevada that will take a specific dog, with the estimated pet fee for the stay.

Every amount is the hotel's pet fee, never the room rate: DogPolicies has no room prices.

Each hotel is sorted into "match" (the policy says yes on everything asked), "possible" (nothing rules it out, but something needs a call: a hotel that decides case by case, an unstated weight limit, a limit the hotel lifts with its approval, an "up to" fee) or excluded (left out). Matches come first, cheapest pet fee first. The fee arithmetic is spelled out for every result.

Examples:
- "Will a Monterey hotel take my 70 lb Lab for under $50?" -> county="Monterey", dog_weight_lb=70, max_total_fee=50
- "Two dogs, three nights near Palm Springs" -> near={lat:33.83, lon:-116.55}, dogs=2, nights=3
- "Is the Motel 6 in Fresno dog friendly?" -> query="Motel 6 Fresno"
- "A Las Vegas hotel for my 60 lb dog" -> county="Clark", state="NV", dog_weight_lb=60

Annotations: read-only true, destructive false, idempotent true, open-world false.

| Input | Type | Meaning |
|---|---|---|
| `query` | string (min length 2, max length 100) | Words in the hotel name, city or brand |
| `brand` | `best-western`, `extended-stay-america`, `kimpton`, `la-quinta`, `motel-6`, `red-roof` | Only this hotel brand |
| `dog_weight_lb` | number (min 1, max 250) | The dog's weight in pounds |
| `dogs` | integer (min 1, max 4, default `1`) | Number of dogs |
| `nights` | integer (min 1, max 30, default `1`) | Nights of the stay |
| `max_total_fee` | number (min 0, max 5000) | Most the guest will pay in pet fees for the whole stay, USD |
| `include_possible` | boolean (default `true`) | Include hotels that need a call to confirm |
| `state` | `CA`, `NV` | "CA" or "NV". Also tells apart counties with the same name, such as Humboldt. |
| `county` | string (min length 2, max length 40) | County name without "County", in California or Nevada, e.g. "Monterey" or "Washoe" |
| `region` | `north-coast`, `shasta-cascade`, `gold-country`, `high-sierra`, `bay-area`, `central-coast`, `central-valley`, `inland-empire-deserts`, `los-angeles`, `orange-county`, `san-diego`, `reno-tahoe-nevada`, `las-vegas-southern-nevada`, `northern-central-nevada` | Region id, e.g. central-coast, san-diego or reno-tahoe-nevada |

## `dogpolicies_route_stops`

**Dog stops along a highway** · since 0.1.0

Dog-friendly stops along a California or Nevada highway, in driving order: rest areas (Caltrans rest areas with pet areas; Nevada rest areas, where leashed dogs are allowed), travel stops with dog parks, hotels, cabin resorts and campgrounds or RV parks near the road (all checked against the dog's weight and the pet-fee budget) and parks or beaches that allow dogs.

Each stop has its mile on the route and its distance off the road. Each route covers one state and stops at the state line. California miles follow the Caltrans odometer: north on I-5 (from the Mexican border), US-101 (from Los Angeles), Highway 1 (from Dana Point) and I-15 (i-15, San Diego to Primm); east on I-80 (i-80, San Francisco to the Nevada line) and US-50 (us-50, West Sacramento to Stateline). Nevada routes count Nevada mileposts from the California line, matching the exit numbers: north on I-15 (i-15-nevada), east on I-80 (i-80-nevada) and US-50 (us-50-nevada, Stateline to Utah); north on US-95 (us-95-nevada, California line to Oregon) and US-93 (us-93-nevada, Hoover Dam to Idaho), whose miles include the stretches they share with other highways. Where Highway 1 runs on US-101, stops on that stretch say so in on_road. A starting point is set with from_mile or near, plus a direction; ahead_miles limits the window to that many miles from the start in the direction of travel.

On I-5 in California each stop also carries its position on the I-5 centerline in meters from San Ysidro (s_m), miles_ahead of the start along the direction of travel, the side of the road it serves (right or left of northbound travel, or both), its distance off the freeway, the road's elevation in meters and the stretch (strip) it is in, plus restrooms, water, pet_area, dog_park and hours as its official source states them. With family=true only stops whose official source states restrooms and a pet area or dog park are returned. With paired=true the result also lists paired stops: a freeway exit in the window with places to stop for people nearby (located through OpenStreetMap, counted by kind, never named and not verified for restrooms) matched to the nearest DogPolicies place that allows dogs within about a mile, with its rule and source.

Routes covered: I-5 (i-5, 796 miles), US-101 (us-101, 809 miles), Highway 1 (highway-1, 736 miles), I-15 (i-15, 294 miles), I-80 (i-80, 204 miles), US-50 (us-50, 109 miles), I-15 (i-15-nevada, 124 miles), I-80 (i-80-nevada, 410 miles), US-50 (us-50-nevada, 409 miles), US-95 (us-95-nevada, 664 miles), US-93 (us-93-nevada, 526 miles).

Examples:
- "Driving north on I-5 from Los Angeles with a 70 lb dog, where can we stop?" -> near={lat:34.05, lon:-118.24}, direction="north", dog_weight_lb=70
- "Pet areas on the Grapevine" -> from_mile=170, to_mile=222, kinds=["rest_area","park"]
- "Next place in 40 miles where the whole family can use a restroom, dog included, northbound at Harris Ranch" -> near={lat:36.25, lon:-120.25}, direction="north", ahead_miles=40, family=true
- "Exits with a coffee shop and a park for the dog between Sacramento and Redding" -> from_mile=520, to_mile=680, paired=true
- "Heading south on 101 from San Francisco to Santa Barbara, where can the dog run?" -> route="us-101", near={lat:37.77, lon:-122.42}, to_mile=100, direction="south"
- "Dog-friendly hotel near Redding under $40 a night" -> near={lat:40.59, lon:-122.39}, kinds=["lodging"], max_total_fee=40
- "Driving I-80 east from Reno with a dog, where can we stop?" -> route="i-80-nevada", near={lat:39.53, lon:-119.81}, direction="east"

Annotations: read-only true, destructive false, idempotent true, open-world false.

| Input | Type | Meaning |
|---|---|---|
| `route` | `i-5`, `us-101`, `highway-1`, `i-15`, `i-80`, `us-50`, `i-15-nevada`, `i-80-nevada`, `us-50-nevada`, `us-95-nevada`, `us-93-nevada` (default `"i-5"`) | Route id |
| `near` | object | Start from the route mile nearest this point |
| `from_mile` | number (min 0, max 1000) | Start at this route mile |
| `to_mile` | number (min 0, max 1000) | Stop at this route mile |
| `ahead_miles` | number (min 1, max 1000) | Window in miles from the start (near or from_mile) in the direction of travel; an alternative to to_mile |
| `direction` | `north`, `south`, `east`, `west` (default `"north"`) | Direction of travel. Route miles increase going north, or east on I-80 and US-50; north and east both mean increasing miles |
| `kinds` | array of `rest_area`, `stop`, `lodging`, `campground`, `cabins`, `park`, `beach`, `trail`, `restaurant` | Kinds of stops to include; all by default |
| `family` | boolean (default `false`) | Only stops whose official source states restrooms and a pet area or dog park (I-5 in California) |
| `paired` | boolean (default `false`) | Also list the paired stops in the window: an exit with people-stops nearby and the nearest dog-legal place (I-5 in California) |
| `dog_friendly_only` | boolean (default `true`) | Leave out stops where dogs are not allowed |
| `dog_weight_lb` | number (min 1, max 250) | The dog's weight in pounds |
| `dogs` | integer (min 1, max 4, default `1`) | Number of dogs |

Output fields: `as_of`, `license`, `attribution_text`, `attribution_url`, `total`, `count`, `offset`, `has_more`, `stops`, `route`, `guide`, `start`, `paired_stops` (more may be added; none removed).

## `dogpolicies_i5_corridor`

**I-5 corridor by stretch** · since 0.3.0

The I-5 corridor in California as eleven named stretches (strips) on the I-5 centerline, from San Ysidro (s = 0 m) to the Oregon line (s ≈ 1,281,400 m), and the dog stops in any stretch, mile range or window ahead of a point. Every stop carries its s in meters from San Ysidro, its Caltrans odometer mile, the side of the road it serves (right or left of northbound travel, or both), its distance off the freeway, the road's elevation, and restrooms, water, pet area, dog park and hours as its official source states them. A family stop is one whose official source states restrooms and a pet area or dog park. A paired stop is a freeway exit with places to stop for people nearby (located through OpenStreetMap, counted by kind, never named and not verified for restrooms) matched to the nearest DogPolicies place that allows dogs within about a mile, with its rule and source.

With no stretch, miles or point, the result is the list of stretches with their s and mile ranges and stop counts. Strips: sandiego (San Ysidro → Camp Pendleton), orange-la (Camp Pendleton → East LA), grapevine (East LA → Wheeler Ridge), kern-westside (Wheeler Ridge → Kettleman), westside (Kettleman → Santa Nella), delta (Santa Nella → Stockton), sacramento (Stockton → Woodland), valley (Woodland → Williams), tehama (Williams → Red Bluff), shasta (Red Bluff → Mt Shasta), siskiyou (Mt Shasta → Siskiyou Summit).

Examples:
- "What is between the Grapevine and Kettleman?" -> strip="grapevine" (East LA to Wheeler Ridge) and strip="kern-westside" (Wheeler Ridge to Kettleman)
- "The next 5 family stops northbound from Stockton" -> near={lat:37.95, lon:-121.29}, direction="north", family=true, limit=5
- "Every stop between mile 300 and 340" -> from_mile=300, to_mile=340
- "Exits with somewhere for people and a park for the dog in the Sacramento stretch" -> strip="sacramento", paired=true

Annotations: read-only true, destructive false, idempotent true, open-world false.

| Input | Type | Meaning |
|---|---|---|
| `strip` | `sandiego`, `orange-la`, `grapevine`, `kern-westside`, `westside`, `delta`, `sacramento`, `valley`, `tehama`, `shasta`, `siskiyou` | A stretch by id (sandiego, orange-la, grapevine, kern-westside, westside, delta, sacramento, valley, tehama, shasta, siskiyou) |
| `from_mile` | number (min 0, max 800) | Start of a mile range (Caltrans odometer) |
| `to_mile` | number (min 0, max 800) | End of a mile range |
| `near` | object | A point on or near I-5; the window starts at the nearest point of the road |
| `direction` | `north`, `south` (default `"north"`) | Direction of travel from near; north means increasing s |
| `ahead_miles` | number (min 1, max 800, default `50`) | Window in miles from near in the direction of travel |
| `kinds` | array of `rest_area`, `stop`, `lodging`, `campground`, `cabins`, `park`, `beach`, `trail`, `restaurant` | Kinds of stops to include; all by default |
| `family` | boolean (default `false`) | Only family stops |
| `paired` | boolean (default `false`) | Also list the paired stops in the window |
| `dog_friendly_only` | boolean (default `true`) | Leave out stops where dogs are not allowed |

| `offset` | integer (min 0, max 9007199254740991, default `0`) | Stops to skip |
| `response_format` | `markdown`, `json` (default `"markdown"`) | 'markdown' for readable text, 'json' for structured data |

Output fields: `as_of`, `license`, `attribution_text`, `attribution_url`, `axis_version`, `strips`, `window`, `total`, `stops`, `paired_stops` (more may be added; none removed).

## `dogpolicies_i5_conditions`

**I-5 conditions now** · since 0.3.0

Current Caltrans lane closures, road-weather station readings, changeable-message-sign text and chain-control status on I-5 in California, each placed on the I-5 centerline (s meters from San Ysidro and the Caltrans mile) and matched to the nearest DogPolicies dog stop. Conditions come from Caltrans' CWWP2 feeds fetched within the last 15 minutes (fetched_at in the result) and are not verified rules.

The window is a mile range (from_mile, to_mile) or a point with a direction and ahead_miles; with none, the whole of I-5 in California. Needs the network (the document is read from dogpolicies.com); offline the result is an error with code offline.

Examples:
- "Is there a closure or chains on the Grapevine right now?" -> from_mile=170, to_mile=222
- "Weather and closures in the next 60 miles northbound from Redding" -> near={lat:40.59, lon:-122.39}, direction="north", ahead_miles=60

## `dogpolicies_changes_near`

**What changed near a town** · since 0.2.0

Verification events (confirmed, changed, source gone, blocked, disputed) since a date for places within a radius of a town, county or point, newest first. The way to answer "has anything changed around Tahoe since my last trip?" or to re-check a saved itinerary.

Example: "What changed near Monterey since September?" -> place="Monterey", since="2026-09-01"

Annotations: read-only true, destructive false, idempotent true, open-world false.

| Input | Type | Meaning |
|---|---|---|
| `place` | string (min length 2, max length 80) | A city, county or area in California or Nevada, e.g. "Monterey", "South Lake Tahoe", "Washoe County, NV", "Las Vegas", "East Bay" or "Lake Tahoe" |
| `near` | object | A point instead of a town; give one of place or near |
| `radius_miles` | number (min 1, max 100, default `15`) | Search radius in miles around the town or point (an area is its own boundary; the radius is ignored) |
| `since` (required) | string | Date, YYYY-MM-DD |
| `outcome` | `confirmed`, `changed`, `source_gone`, `blocked`, `disputed` | Only events with this outcome |
| `limit` | integer (min 1, max 50, default `10`) | Maximum results to return |
| `offset` | integer (min 0, max 9007199254740991, default `0`) | Results to skip, for pagination |
| `response_format` | `markdown`, `json` (default `"markdown"`) | 'markdown' for readable text, 'json' for structured data |

Output fields: `as_of`, `license`, `attribution_text`, `attribution_url`, `label`, `radius_miles`, `total`, `count`, `has_more`, `events` (more may be added; none removed).

## `dogpolicies_report_correction`

**Report a correction** · since 0.1.0

File a correction when a user says a rule on a record is wrong or has changed (a fee went up, a beach closed to dogs, a hotel now takes two pets). The report goes to a person who re-reads the official source; nothing is published automatically and the record does not change until it is verified. Takes the place id, a sentence or two on what is wrong, and optionally the official page the user saw. The only personal detail it accepts is an optional contact the user offers.

Annotations: read-only false, destructive false, idempotent false, open-world true.

| Input | Type | Meaning |
|---|---|---|
| `place_id` (required) | string (min length 2, max length 120) | Place id from a search result |
| `message` (required) | string (min length 5, max length 2000) | What is wrong, in the user's words |
| `source_url` | string (max length 500) | The official page that shows the current rule, if the user has it |
| `contact` | string (max length 200) | How to reach the reporter, only if they offer it |

Output fields: `report_id`, `place_id`, `status`, `url` (more may be added; none removed).
